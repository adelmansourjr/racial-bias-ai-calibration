# Scope for this research prototype

Untrusted request data may not alter reviewed source roles or call an audit
option. Trusted operator/reviewer configuration controls keys, checkpoint files,
model graph and policy. The host is assumed benign; Python attribute privacy is
not process isolation, and malicious host code can read raw embeddings or keys.

The output theorem covers two accepted requests with the same retained evidence.
Timing, memory, errors, packet sizes, tokenizer CPU work and admission limits
are not protected side channels. Unknown aliases left in evidence can influence
the result. Two credentials can approve the same wrong semantic interpretation.

Never use public fixture keys operationally. Demo/study keys are random,
in-memory and not saved. Never place real CVs or secrets in a public issue or
repository. Model weights and private applicant data are not included in this
release. This code is not approved for real hiring deployment.
