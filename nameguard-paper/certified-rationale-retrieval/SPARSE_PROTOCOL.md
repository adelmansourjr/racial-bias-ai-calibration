# Follow-up on exact sparse evidence alignment

The first experiment found that the weighted-bag bound saved most alignment work and that the ordered-pair bound saved little beyond it. This follow-up fixes a new comparison before running a sparse alignment scorer on SciFact. It reuses the same 209 cases, sentence budgets, rank formula, candidate order, and gold evidence annotations.

Replace dense weighted-longest-common-subsequence dynamic programming with an exact sparse computation over token-equality pairs. For each claim token, process matching sentence positions from right to left. A Fenwick tree records prefix maxima of the total weight attained by matches at earlier sentence positions. The order prevents a claim token from extending another match from the same token. The answer is the final prefix maximum across all sentence positions.

Verify the sparse scores against dense scores on all 2,031 sentence candidates, and use a separate explicit quadratic match-DAG implementation as an oracle on 1,000 fixed-seed random pairs. Compare exhaustive, weighted-bag, and ordered-pair ranking with both kernels. All six must preserve the original exact ranked top two. Report matching-pair counts and Fenwick loop iterations separately, since a loop iteration and dense DP cell have different costs.

Measure process CPU for nine paired, deterministically shuffled timing blocks, each with 12 whole-cohort ranking passes per method, under one local Python process. The timing includes query preparation, sentence counts, BM25, bounds, alignment, and top-two selection. Exclude shared archive loading and corpus-level lexical preprocessing from the main timing, and separately measure their cost once in each block and report an estimated single cold-run CPU total with that cost added back. Report per-pass median and range, plus the median and range of paired timing ratios against dense weighted-bag pruning. This is descriptive one-machine timing. The follow-up tests an implementation optimization on a fixed evidence scorer. It makes no claim about LLM computation or predictive quality.
